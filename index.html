0x AUDIO
BY SUNKEN0X

A grand piano lives on Ethereum.
Anyone can play it. Nobody has to ask.

0x Audio is a shared format for music stored on the blockchain. It does for on-chain sound what the JPEG did for pictures: any tool can open it, anyone can use it, and no one needs permission from the person who made it.

Free forever. CC0. No licence, no gatekeeper, no server to go down.

THE PROBLEM

There is real music on Ethereum already. Pianos, drum kits, whole sample libraries, stored on the chain itself and meant to last forever.

But there is no agreed way to read any of it. Every library is locked to whoever built it. If you want to use someone else's drums in your artwork, you have to message them and hope they explain how. That has actually been happening, one DM at a time.

Sounds on a blockchain that nobody else can open are not really public. They are just stored in the open.

WHAT CHANGES

One agreed shape for the files, so everything fits everything else. Put your sounds in a crate. Write your notes in a score. Any player can read both, including one somebody else wrote.

The crate is the piano. The score is the sheet music. The composer is the pianist. Change any one of them and the other two still work.

That is the whole idea. Swap the crate under the same score and the same tune plays on a different instrument. Hand your score to someone else and it still works, because nothing in it depends on you.

WHAT IT MEANS FOR YOU

IF YOU MAKE MUSIC

no code needed

Put a set of samples on chain once and anyone can build with them, forever. You are not running a service, and there is nothing to maintain. It just sits there and works.

IF YOU MAKE ART

no licence, no server

Use a real instrument in your piece without hosting audio, paying for samples, or asking anyone. The sound is already on the chain. Point at it and play.

IF YOU COLLECT

it cannot break

Art that plays music, where the music is not a link that dies. The instrument, the notes and the picture all live on Ethereum. No server, no expiry.

THE FREE PIANO

To prove it works, there is a grand piano on Ethereum right now. Nineteen recorded notes of a real Kawai grand, put there so anyone can use it. It is CC0, which means it belongs to everyone and costs nothing.

It is not a demo or a promise. It is a file on the blockchain, and this command reads it back: 

cast call 0xFe1411d6864592549AdE050215482e4385dFa0FB \
  "readFile(string)(string)" "audiomaps-piano-v1.bin" --rpc-url <mainnet rpc>

If that means nothing to you, that is fine. It means the piano is real and anyone can check.

FOR PEOPLE WHO BUILD THINGS

Everything below is the actual specification. Skip it unless you are implementing.

THE CRATE, IN FULL

This is not a proposal. It documents a file that is already on Ethereum mainnet.

[4-byte big-endian uint32]   manifest length in bytes
[manifest JSON, UTF-8]       length as above
[audio bytes]                all samples concatenated, no separators

The manifest is a bare JSON array. Each entry is [slot, offset, length]:

[["A2", 0, 25402], ["A4", 25402, 22260], ["B3", 47662, 27032], ...]

Offsets are relative to the start of the audio section, not the file, and they tile contiguously. That is the entire container. No magic number, no version field, no trailer.

THE SCORE, IN FULL

{
  "0xaudio": "score/0.1",
  "bpm": 116,
  "ppq": 480,
  "length": 15360,
  "notes": [
    [0, 52, 1920, 102],
    [0, 71, 480, 96],
    [480, 67, 480, 90]
  ]
}

A note is four integers, positional: [start, note, duration, velocity]. A reader must reject any file whose 0xaudio tag it does not recognise.

THE REFERENCE CRATE

A grand piano. On chain, CC0, free for anyone to load. Read it yourself:

FILEaudiomaps-piano-v1.bin
STOREEthFS FileStore 0xFe1411d6864592549AdE050215482e4385dFa0FB
STORED593,224 base64 characters
DECODED444,916 bytes
CONTENTS19 Opus-in-Ogg samples, VCSL Kawai piano
cast call 0xFe1411d6864592549AdE050215482e4385dFa0FB \
  "readFile(string)(string)" "audiomaps-piano-v1.bin" --rpc-url <mainnet rpc>

The FileStore sits at the same address on every chain EthFS supports, so that address is not mainnet-specific.

WHERE IT IS UP TO

  • Crate spec, v0.1 — written against a file already on chain
  • Score spec, v0.1
  • Player — no dependencies, no build step, runs from file://
  • Inspector — conformance checker with a face on it
  • Conformance spec — what adheres means, per role
  • Effects, and hosts that patch tools together. Hosts must be many, never one, or the standard quietly becomes a platform.
  • Sync, a wire protocol rather than a file format, further out.

The standard exists. Tools are coming.

USING IT

Take any of it. Put your own sounds in a crate and the player will read them. Write a score against someone else's crate and it will play. Fork the player, throw it away, write a better one. That is what a format is for.
